Project overview

The ESP32 reads temperature and humidity from a DHT11 and ambient light from an LDR. It uploads each reading to Firebase, where the Task 4 dashboard updates live. In the other direction, the ESP32 reads the dashboard's control mode and light threshold, then switches a relay-connected bulb manually or automatically.

GPIO 34 is on ADC1, which remains usable while Wi-Fi is active. The LDR and 10 kΩ resistor form a voltage divider; a bare four-pin DHT11 needs a pull-up on its data line.

Firmware and data handling

Sensor sampling

The DHT11 is sampled at its supported interval of about two seconds. The ESP32 takes 15 LDR samples and averages them to soften noisy analog readings (12-bit ADC range: 0–4095).

Manual and automatic modes

Manual mode follows the bulb command stored in Firebase. Automatic mode compares the averaged light reading with the configured threshold and controls the relay accordingly.

Database records

The database keeps user bulb control, operating mode, light threshold, and timestamp-keyed readings. Each reading includes temperature, humidity, light intensity, and relay state.

Libraries and tools

Arduino IDE, ESP32 Arduino core, DHT sensor and Adafruit Unified Sensor libraries, Firebase Arduino Client Library by Mobizt, Firebase Authentication, and Realtime Database.

Firebase data structure

Timestamp-keyed readings retain a history for the dashboard. Authentication identifies authorized users, and database rules control access to user controls and shared settings.

Control and settings

  • users/<uid>/bulb — user's bulb command
  • settings/mode — manual or automatic mode
  • settings/threshold — light trigger threshold

Sensor history

  • readings/<unix time> — timestamped record
  • Temperature and humidity
  • Light intensity and relay state

Dashboard capabilities

  • Google sign-in and authenticated access
  • Live temperature, humidity, and light readings
  • Manual bulb ON/OFF and automatic operating mode
  • Adjustable light threshold and historical readings
  • CSV export and connection status

Observed results and implementation notes

Reported test timing

  • Sensor reading interval: about 2 seconds
  • Dashboard synchronization: about 1–2 seconds
  • Relay response: about 10 ms
  • Firebase database reads: about 50–200 ms
  • Realtime stream updates: generally under 1 second

Challenges addressed

  • Smoothed noisy LDR readings with 15-sample averaging
  • Kept DHT11 sampling to its supported interval
  • Used ADC1 GPIO34 to avoid ADC2 and Wi-Fi conflicts
  • Used a flatter Firebase structure for easier access
  • Placed the relay OFF when Wi-Fi or Firebase is unavailable

Outcome

The completed system links physical sensing, cloud storage, and web control. Sensor readings reach the dashboard in near real time, and relay commands travel back to the ESP32. If Wi-Fi or Firebase communication is lost, the firmware places the relay in the OFF state.

The project demonstrates how embedded sensors, cloud databases, authentication, and a web interface can operate as one system. It also highlights the value of filtering noisy sensor data and using realtime listeners to keep the dashboard current without page refreshes.

20. Current Prototype Limitations

The prototype demonstrates the integration of an ESP32, sensors, Firebase, and a web dashboard. These areas could be improved in future development:

No.LimitationExplanation
01Sensor accuracyDHT11 provides basic temperature and humidity measurements and is less accurate than advanced environmental sensors.
02Light measurementThe LDR provides relative light readings rather than calibrated illumination in lux.
03Internet dependencyFirebase communication requires an active internet connection.
04Network reliabilityUnstable Wi-Fi can interrupt data transmission and remote appliance control.
05Data update intervalSensor readings are uploaded at a fixed two-second interval.
06Local account storageThe supplied dashboard account interface uses browser LocalStorage rather than demonstrating a complete cloud authentication system.
07Hardware expansionThe current prototype supports a limited number of sensors and controlled appliances.
08Power managementContinuous operation of the ESP32, sensors, and relay requires reliable power management.
Key observation: The prototype is suitable for demonstrating basic IoT monitoring and appliance control. Improving reliability, sensor accuracy, security, and scalability would make it more suitable for practical applications.

22. Final Learning Reflection

Working on this smart home IoT project helped me understand how hardware, programming, cloud services, and web technologies can be combined to develop a connected application.

Initially, I focused on the ESP32, DHT11, LDR, and relay module. Later, I explored how sensor readings could be transmitted to Firebase and displayed through a web dashboard.

One important learning experience was understanding communication between the ESP32 and Firebase. I also gained knowledge of JavaScript-based dashboard development, database operations, and remote appliance control.

I learned that an IoT system involves more than connecting hardware and writing code. Network reliability, data accuracy, security, power management, and user experience are equally important. This project improved my practical understanding of IoT and gave me confidence to explore more advanced cloud-connected automation systems.
