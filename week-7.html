Week 7 — Arduino Embedded Systems & IoT Cloud Web Applications

Week 7 covered microcontroller programming, firmware architectures, IoT cloud platforms, and building full-stack web applications with Firebase Authentication and Hosting. Building on the hardware foundation from Week 6, this week moved from programming individual microcontrollers to connecting devices to the internet and controlling them remotely through cloud platforms and web interfaces.

Computational Hardware & Embedded Systems — Continuation

We continued our hardware learning from Week 6 by working with Arduino boards. As a first exercise, we tested LED blinking, which is the basic “Hello World” program of embedded systems and a simple way to confirm that the board, the code, and the circuit are all working correctly. We then learned the basics of the Arduino IDE, including how to write, compile, and upload a program to the board, and studied the functions of the different pins, such as digital, analog, and PWM pins, and how they are used to interface with peripherals like LEDs, sensors, and other components. We also explored embedded simulators and emulators, which allow circuits and code to be tested on a computer before using real hardware, saving time and reducing the risk of damaging components. We studied the five-block architecture of an embedded system to understand the main building blocks of an embedded system and how they work together. We learned how a processor runs its program in a continuous polling loop, repeatedly checking inputs and updating outputs, which is the structure followed by the setup() and loop() functions in Arduino. In addition, we learned the fundamentals of C and Embedded C programming, which are used to write efficient firmware for microcontrollers, and deepened our understanding of the digital NOT gate and inverter logic principles first introduced in Week 6.

Session: Internet of Things (IoT)

Later in the week, we attended a dedicated session on the Internet of Things (IoT). The session explored how everyday devices can be connected to the internet, and covered connected devices, sensors, actuators, communication protocols, and remote device control. We learned how sensors collect data, how that data is sent over a network to a cloud platform or server, and how actuators can be controlled remotely through commands sent from a dashboard or web application. The session included three practical projects.

Adafruit Cloud Bulb Control

In the first project, we used the Adafruit IO cloud platform to control a bulb remotely. We configured Adafruit IO feeds, which store and transfer data between the device and the cloud, and created a dashboard with controls to switch the bulb on and off. We then wrote C code in the Arduino IDE to connect the microcontroller to Wi-Fi and to the Adafruit IO feed, so that it could receive commands from the dashboard. Finally, we tested remote ON/OFF control of the bulb over Wi-Fi. This project showed me how a cloud platform acts as a link between the user and the device, allowing hardware to be controlled from anywhere with an internet connection.

Firebase Web Application

In the second project, we built a beginner-friendly web application using Firebase. The application included a responsive landing page that adjusts to different screen sizes, along with user registration and login using Firebase Email/Password Authentication. We created a protected dashboard that only logged-in users can access, using the onAuthStateChanged() function to check whether a user is signed in and redirect them if they are not. We also added a logout feature using the signOut() function. Finally, we deployed the application online using the Firebase Hosting CLI, making it accessible through a live web link. This project gave me practical experience in building a complete web application, from the user interface to secure authentication and online deployment.

ESP32 Local Web Server

In the third project, we configured an ESP32 microcontroller as an HTTP local web server. The ESP32 connected to the local Wi-Fi network and served a web page that could be opened in a browser on any device connected to the same network. This web interface included controls to toggle connected LEDs and relay-driven bulbs in real time. The relay module allowed the low-voltage ESP32 to safely switch a higher-voltage bulb. This project helped me understand how a microcontroller can host its own web page and respond to requests from a browser, making it possible to control devices directly over a local network without relying on an external cloud service.

Overall, Week 7 was a valuable learning experience that connected embedded programming with the Internet of Things. Working with Arduino boards, embedded C, and the five-block embedded architecture strengthened my understanding of how microcontrollers run firmware and interact with peripherals. The IoT projects with Adafruit IO, Firebase, and the ESP32 web server showed me different ways of connecting devices to the internet and controlling them remotely, while building and deploying the Firebase web application gave me practical experience in full-stack development, authentication, and hosting.
