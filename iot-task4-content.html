Dashboard and hardware connection

The ESP32 gathers temperature and humidity from a DHT11 sensor and ambient light from an LDR. It samples the sensors every two seconds and smooths the light readings to reduce small fluctuations. Readings travel over Wi-Fi to Firebase, where the web dashboard can display them.

Relay commands travel back through Firebase to the ESP32, which switches the connected appliance. The relay in this setup is active-LOW: a LOW GPIO signal activates it, and a HIGH signal deactivates it. The dashboard keeps sensor readings, connection status, and relay state in separate areas so each is easy to understand.

Data flow
Sensors → ESP32 → Wi-Fi → Firebase → Dashboard
Dashboard → Firebase → ESP32 → Relay → Appliance

IoT Session — Task 4: Forge Web Dashboard

1. Overview

Objective

The goal of this task is to create a responsive three-page dashboard for Forge using HTML, CSS, and JavaScript. The dashboard allows users to view sensor readings and control a bulb from different screen sizes.

Problem Being Addressed

In earlier tasks, the ESP32 was controlled through a local web page, an Adafruit IO dashboard, and Google Assistant. None of these provided Forge with its own dedicated interface. This task creates a single, clean place for sign-in, live monitoring, bulb control, mode selection, and data download.

This interface is built before the hardware is connected. Firebase is set up through a placeholder configuration file, and the real values are added in Task 5.

Project Summary

This project is a three-page web app: a landing page, a login page, and a dashboard. The dashboard displays live temperature, humidity, and light values, includes an animated bulb toggle, provides manual and automatic modes, has a light-sensitivity slider, shows a history table, and supports CSV export.

Basic operation: User → Landing Page → Login Page → Dashboard → Firebase Realtime Database

2. Concepts

Dashboard

The web page used to see the sensor data and control the bulb. Here it is a small three-page web app, built on its own before any hardware is connected.

Three-Page Web App

A landing page announcing Forge, a login page, and the dashboard itself.

HTML, CSS and JavaScript

The three languages of every web page: HTML is the structure, CSS is the look, JavaScript is the behaviour. Forge uses only these, with no framework.

State Management

Keeping track of what the page currently knows, for example whether the bulb toggle is a manual command or the automatic mode's decision.

Mode Selector

The control that switches between manual and automatic.

Light-Sensitivity Slider

The slider that sets the threshold (0–4095) used in automatic mode.

History Table

The list of the latest recorded readings.

CSV Export

One click downloads the recorded temperature, humidity and light as a spreadsheet file.

Input Validation

Checking what a user types before it is used, so bad values never reach the database.

Loading and Error States

What the page shows while data is still arriving, and what it says when something goes wrong, instead of a blank screen.

Responsive CSS

Styles that adapt to the screen size. The dashboard was tested on phone, tablet and desktop.

Transition Animation

A short smooth change between two states. Without it the toggle felt dead; with it the same response felt instant.

Perceived Performance

How fast something feels rather than how fast it is. Users do not care about the stack, they care that clicking ON turns the light on.

3. System Design

System Architecture

The complete system contains four major elements:

User → Web Dashboard (Browser) → Firebase (Auth + Realtime Database) → ESP32 → Bulb

In this task only the first two parts are built and checked. The Firebase and ESP32 connection is completed in Task 5.

Data Flow

  1. The user opens the landing page and selects Sign in.
  2. The login page validates the email and password and signs in with Firebase Authentication (or Google).
  3. If the user is already signed in, the login page redirects straight to the dashboard.
  4. The dashboard checks the sign-in state and redirects to the login page if nobody is signed in.
  5. Real-time listeners read the bulb state, settings and latest 20 readings from the database.
  6. The page redraws cards, bulb, mode and history table whenever data changes.
  7. The user toggles the bulb, changes the mode or moves the slider; the change is written to the database.
  8. The user can export up to the latest 5000 readings as a CSV file

11. Important Code Sections

These JavaScript patterns protect the dashboard, keep its Firebase data current, control how relay state is displayed, validate settings, and export readings.

11.1 Authentication Guard

The authentication guard allows only signed-in users to access the dashboard. Firebase Authentication checks the login state, and the user's unique ID (UID) becomes the root of that user's database path.

Dashboard authentication JAVASCRIPT
onAuthStateChanged(auth, (user) => {
  if (!user) {
    location.replace("login.html");
    return;
  }

  base = "users/" + user.uid;
  start();
});

Check sign-in

Firebase reports whether a user is currently authenticated.

Protect the dashboard

Unauthenticated visitors are redirected to the login page.

Scope user data

The authenticated UID sets the user's database root before the dashboard starts.

11.2 Real-Time Firebase Listeners

11.3 Manual and Automatic Display Logic

The display logic uses the requested state in manual mode and the latest reported relay state in automatic mode.

Mode-based relay display JAVASCRIPT
const on = mode === "auto"
  ? !!(latest && latest.relay)
  : bulbWanted;

toggle.checked = on;
toggle.disabled = mode === "auto";

Manual modeDisplays the user's requested bulb state.
Automatic modeDisplays the actual relay state from the latest data.
Toggle controlDisabled in automatic mode to prevent a manual override through this toggle.

This keeps the display aligned with the selected operating mode.

The ESP32 is the hardware controller in the smart home IoT system. It reads environmental sensors, communicates with Firebase over Wi-Fi, receives appliance commands, and controls the relay module.

18.2 Hardware Pin Configuration

ComponentESP32 pinFunction
DHT11GPIO 4Temperature and humidity
LDRGPIO 34Analog light measurement
Relay moduleGPIO 5Appliance switching

18.3 ESP32 Communication Workflow

  1. Power on and initialize the ESP32.
  2. Connect to Wi-Fi.
  3. Connect to Firebase.
  4. Read temperature and humidity from the DHT11.
  5. Read the LDR value.
  6. Upload sensor readings to Firebase.
  7. Read the bulb control command.
  8. Activate or deactivate the relay based on the command.
  9. Print status to Serial Monitor and repeat the cycle.

ON command

Activate the relay and report the bulb ON state.

OFF command

Deactivate the relay and report the bulb OFF state.

18.4 Important Programming Concepts

Wi-Fi connectivity

The ESP32 joins the configured wireless network using the WiFi.h library.

Sensor data acquisition

The DHT library reads temperature and humidity; analogRead() reads the LDR.

Firebase communication

Firebase_ESP_Client uploads readings and retrieves bulb-control commands.

Relay automation

The ESP32 checks the received Boolean value and changes the relay output.

Periodic execution

millis() schedules sensor updates every two seconds without blocking the main loop with a delay.

18.5 Important Code Snippets

Sensor reading

Sensor acquisition ARDUINO / C++

Upload sensor data to Firebase

Firebase Realtime Database writes ARDUINO / C++
Firebase.RTDB.setFloat(&fbdo, "/IoT/sensors/temperature", temperature);
Firebase.RTDB.setFloat(&fbdo, "/IoT/sensors/humidity", humidity);
Firebase.RTDB.setInt(&fbdo, "/IoT/sensors/ldr", ldrValue);

Relay control

Read command and switch relay ARDUINO / C++
if (Firebase.RTDB.getBool(&fbdo, "/IoT/control/bulb")) {
  bool bulbState = fbdo.boolData();

  if (bulbState) {
    digitalWrite(RELAY_PIN, HIGH);
    Serial.println("Bulb: ON");
  } else {
    digitalWrite(RELAY_PIN, LOW);
    Serial.println("Bulb: OFF");
  }
}
