Google Assistant Voice Control via IFTTT

1. Project Overview

The Google Assistant Voice Control via IFTTT project adds a voice-control layer to the previously developed MQTT-based IoT system.

The system allows a user to control a physical AC bulb using a voice command. When the user speaks a predefined command through Google Assistant, the voice input is processed and passed to IFTTT (If This Then That). IFTTT then triggers a Webhook request that communicates with the cloud platform.

The cloud platform updates the corresponding MQTT feed, and the ESP32 receives the command through its existing MQTT connection. The ESP32 then changes the relay state, which controls the connected AC bulb.

This creates an end-to-end voice-controlled IoT system connecting voice recognition, cloud automation, web APIs, MQTT communication, embedded hardware and electrical actuation.

2. Project Objective

The main objective was to develop a voice-controlled IoT automation system that allows a user to operate a physical electrical load without directly interacting with a web dashboard.

The project focuses on:

  • Integrating voice commands with an IoT system
  • Understanding voice-based automation
  • Using IFTTT as an automation layer
  • Understanding Webhook-based HTTP communication
  • Connecting Webhooks with cloud IoT services
  • Integrating voice control with MQTT
  • Controlling physical hardware through a voice command
  • Understanding multi-platform IoT architecture
  • Creating a hands-free control interface

6. Voice Command Layer

The user starts the process by speaking a predefined command.

Example:

"Hey Google, activate bulb on"

The voice assistant processes the spoken input and identifies the configured trigger.

The voice command therefore acts as the human-machine interface for the IoT system.

Instead of manually opening a dashboard and pressing a button, the user can initiate the same control operation using a voice command.

7. Google Assistant

Google Assistant acts as the first interaction layer between the user and the automation system.

The general process is:

User speaks

    ↓

Google Assistant receives voice

    ↓

Speech recognition

    ↓

Intent identification

    ↓

Configured trigger detected

    ↓

IFTTT automation activated

The voice interface converts a natural-language command into a predefined automation event.

8. IFTTT Automation Layer

IFTTT stands for:

If This Then That

It provides an automation mechanism in which one event triggers an action.

For this project:

IF

Voice trigger is detected

THEN

Send Webhook request

The IFTTT applet therefore acts as the bridge between the voice interface and the IoT cloud system.

9. Webhook Communication

After the IFTTT trigger is activated, the system sends an HTTP request through a Webhook.

The Webhook acts as a bridge between IFTTT and the cloud IoT platform.

Conceptually:

IFTTT

   │

   │ HTTP POST

   ▼

Adafruit IO API

The request contains the required control value.

For example:

ON

or:

OFF

The cloud platform then processes the received value and updates the corresponding feed.

10. Adafruit IO Integration

Adafruit IO acts as the cloud communication layer between IFTTT and the ESP32.

The control sequence is:

This allows the voice-control system to use the same MQTT infrastructure developed in the previous project.

11. MQTT Communication

The ESP32 remains connected to the MQTT broker and subscribes to the relevant control feed.

When Adafruit IO receives the updated value, it publishes the corresponding MQTT message.

For example:

Voice Command

     ↓

IFTTT

     ↓

Adafruit IO

     ↓

MQTT Message: ON

     ↓

ESP32

The ESP32 receives the MQTT message and processes the command.

This means the voice-control layer can be added without replacing the existing MQTT-based device architecture.

12. ESP32 Hardware Control

After receiving the MQTT command, the ESP32 changes the state of its GPIO output.

The GPIO output controls the relay module.

MQTT Command

     ↓

ESP32

     ↓

GPIO Output

     ↓

Relay Driver

     ↓

Relay Contact

     ↓

AC Load

For an ON command:

GPIO → Relay Activated → Contact Closed → Bulb ON

For an OFF command:

GPIO → Relay Deactivated → Contact Open → Bulb OFF

13. Relay and AC Load

The relay provides the interface between the ESP32's low-voltage control system and the 230V AC load.

The ESP32 does not directly switch the 230V supply.

Instead:

Low Voltage Side

ESP32

  ↓

GPIO

  ↓

Relay Module

High Voltage Side

230V AC

  ↓

Relay Contact

  ↓

Bulb

The relay electrically separates the control circuitry from the switched load according to the relay/module's design and ratings.

14. High-Voltage Safety

Because the project involves 230V AC, the mains section requires appropriate electrical safety precautions.

The relay should be appropriately rated for the connected load and voltage.

The AC switching circuit should:

  • Switch the Live conductor appropriately.
  • Use properly rated relay contacts.
  • Use suitable wires and terminals.
  • Keep mains connections insulated and enclosed.
  • Prevent accidental contact with energized conductors.
  • Keep low-voltage and mains wiring physically separated.
  • Disconnect mains power before modifying the circuit.
  • Use appropriate protection and earthing where required.
  • Be inspected or assembled by a qualified electrician for practical deployment.

The ESP32 side should remain a low-voltage control circuit and should never be directly connected to the 230V supply.
